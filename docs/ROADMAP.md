## 一、确认的缺口

这些不是设想，是当前代码里确实缺失或重复的东西。

### K-01 · 没有自定义 404 页 · 工作量 小

> **已完成**

**证据**：`src/pages/404.astro` 不存在；Vercel 路由表中 `^/404/?$` 落到框架默认页。

访客走到失效链接时看到的是 Astro 的裸默认页，没有导航、没有搜索入口、不带站点外观。补一个 404 页可以顺手放上搜索框和最近文章，把死路变成入口。

### K-02 · 没有社交分享图（OG image） · 工作量 中

> **已完成**

**证据**：全项目搜索 `og:image` / `twitter:image` → **0 处**。

文章链接分享到微信、Telegram、X 时不会显示预览图，只有一行标题。`Layout.astro` 已经写了完整的 `og:title` / `og:description`，只差图。可以给每篇文章用 banner 图，或用 Astro 端点在构建期生成带标题的卡片图。

### K-03 · 三个展板页，两个内容完全相同 · 工作量 小

> **已完成**

**证据**：

| 页面 | 渲染内容 |
| --- | --- |
| `gallery.astro` | `DashboardPanel`（MainGridLayout） |
| `dashboard.astro` | `DashboardPanel`（DashboardLayout） |
| `test-dashboard.astro` | 仅 `CountdownModule`，标题「测试展板」 |

`/gallery/` 与 `/dashboard/` 渲染同一个组件，只是外层布局不同；`/test-dashboard/` 是开发遗留，会随构建上线并进 sitemap。建议留一个正式入口，另两个删掉或改成重定向。

### K-04 · 标签与分类页不可索引 · 工作量 中

> **已完成**

**证据**：`getTagUrl()` → `/archive/?tag=xxx`（查询参数，客户端筛选）。

标签和分类靠 `/archive/` 上的查询参数做前端过滤，搜索引擎抓不到、也进不了 sitemap，等于每个标签都没有自己的页面。改成真实静态路由 `/tags/[tag]/` 与 `/categories/[category]/` 后可被索引、可直接分享，归档页的交互式筛选可以保留不动。

## 二、性能

数字取自 `pnpm build` 后的 `dist/client/_astro/`，**未压缩**。

### K-05 · 分享功能的二维码/条形码库进了每篇文章的首屏 · 工作量 小

> **已完成**

**证据**：`PostActions.js` — **94 KB**。调用链：`PostActions`（`client:load`）→ 静态 import `ShareModal` → 静态 import `jsbarcode` + `qrcode`。

分享弹窗默认是关着的，但它依赖的两个库在每篇文章打开时就被下载解析。把 `ShareModal` 改成点击时 `await import()` 动态加载，这 94 KB 里的绝大部分可以从首屏移走 —— **投入产出比最高的一项**。

### K-06 · AI 总结组件同样是 client:load · 工作量 小

> **已完成（组件整体移除）**

**证据**：`AISummary.js` — **113 KB**（全站最大的 JS 产物）。

它在文章正文之上，但内容要用户主动触发才生成。改成 `client:visible` 或 `client:idle` 可以让它不参与首屏阻塞，交互体验几乎无差别。

### K-07 · CSS 产物合计 476 KB · 工作量 中

> **已完成 · 504→404 KB**

**证据**：`dist/client/_astro/*.css` 合计 **476 KB**，单个最大 `Layout.css` — 65 KB。

Tailwind 4 迁移时观察到 `@apply` 组合会产生重复声明（同一个 `content:var(--tw-content)` 在一条规则里出现多次）。把高频组件类从 `@apply` 链改写成直接的 CSS 属性，能明显压掉体积，按 Tailwind 官方建议也更快。

## 三、功能建议

每一项都基于代码里已经存在的结构，不是凭空加模块。

### K-08 · 系列 / 专栏 · 工作量 中

> **已完成**

**落点**：现有文章已用目录分组 —— `posts/0510-1/`、`posts/old-1/`。

你写长文时已经在用目录分组了，但站点不认这层结构。在 frontmatter 加 `series` 与 `order` 字段，文章页顶部显示「本系列第 N 篇」和同系列目录，多篇连载的阅读路径会顺很多。

### K-09 · 相关文章推荐 · 工作量 小

> **已完成**

**落点**：当前文章底部只有「上一篇 / 下一篇」（按时间），无相关性推荐。

标签和分类数据已经齐了，按标签重合度算个简单打分就能在文末给出 3 篇相关文章，比纯时间顺序更容易留住读者。

### K-10 · 阅读进度条 · 工作量 小

> **已完成**

**落点**：已有 `TimeProgress`（时间进度）与音乐播放进度，但**无文章阅读进度**。

最长的一篇文章有 56 个标题锚点，长文没有进度反馈。导航栏底部加一条细进度线即可，和已有的 TOC 高亮联动效果更好。

### K-11 · 语言切换器 · 工作量 中

> **已撤销 · 曾实现完整的中英双语路由，后按需求整体移除，回到单语言站点**

**落点**：已内置 **10 套语言文件**（en / ja / ko / es / id / th / tr / vi / zh_CN / zh_TW），但语言由 `config.ts` 构建期写死，无切换入口。

翻译资产已经躺在那儿了却没有出口。最轻的做法是加一个前端语言切换（只切界面文案，不切文章）；彻底一点则走 Astro 的 i18n 路由做多语言站点。

### K-12 · 评论数显示 · 工作量 中

> **部分完成 · 文章页已显示；列表卡片需 GitHub token。相关的「评论小字翻译」已随多语言一并取消**

**落点**：giscus 已接入（`Comment.astro`），但列表页与文章头部不显示评论数。

文章卡片上有字数和阅读时长，缺一个「N 条评论」。可以通过 GitHub Discussions API 在构建期取数，或用 giscus 的前端事件回填。

### K-13 · 友链可用性巡检 · 工作量 中

> **已完成**

**落点**：友链数据在 `src/friends.ts`，页面统计了总数/置顶数，但无存活检测。

友链站点关站、换域名是常态。加一个定时任务（GitHub Actions）批量探活，把失效的标灰或列出来，省得手动逐个点。

## 四、UI 改进

### K-14 · 空状态设计 · 工作量 小

> **已完成**

**证据**：`main` 分支零文章时，首页与归档页无空状态提示；构建期打印 `collection "posts" is empty`。

Kirari 现在是可以给别人用的模板，别人第一次跑起来看到的就是空白首页。加一个「还没有文章，用 `pnpm new-post` 开始」的引导，第一印象完全不同。展板各模块在数据为空时也可以做同样处理。

### K-15 · 展板的信息层级 · 工作量 中

> **部分完成 · 已加头部与入场编排，模块主次未调**

**证据**：`DashboardPanel` 现有 6 个模块，均为同等视觉权重的卡片纵向堆叠。

日历、倒计时、微新闻、待办、成绩、抽签平铺在一起，没有主次。把最需要一眼看到的（倒计时 / 待办）放大或置顶，其余收进次级密度，扫读效率会明显提升。

### K-16 · 成绩模块的数据来源 · 工作量 小

> **已完成**

**证据**：`ScoreboardModule.svelte` 中科目、分数、等级硬编码在组件里，标题写死「中考」。

其他模块都从 `public/*.json` 读数据，只有它把数据写死在代码里，改一次成绩要动组件。抽到 JSON（如 `scoreboard.json`）后既统一了模式，也让这个模块对模板使用者有意义。

### K-17 · 移动端的展板与表格 · 工作量 中

> **部分完成 · 成绩表已改横向滚动**

**证据**：公告文案原文写着「强烈建议使用平板、电脑等宽屏设备访问本站」。

需要用公告提醒用户换设备，本身就说明窄屏体验没做到位。成绩表这类宽内容可以在窄屏改成卡片式纵向排列，而不是让用户横滑或换设备。

### K-18 · 特效的默认开关 · 工作量 小

> **已取消 · 与「增加生气」的诉求冲突，改为保留氛围、强化微交互**

**证据**：`SpecialEffects` 中五彩纸屑 / 粒子背景 / 流星 / 聚光灯默认全开。

四种动效同时默认开启，既抢正文注意力也吃低端设备性能。建议默认只留一到两种，并接上 `prefers-reduced-motion`，其余交给设置面板。

## 如果只做三件事

1. **K-05**（分享库改按需加载）—— 改动最小，去掉每篇文章首屏近 94 KB 的无用 JS。
2. **K-02**（社交分享图）—— 直接影响文章被转发时的样子，是目前对外呈现最明显的短板。
3. **K-04**（标签/分类静态路由）—— 让站点内容真正可被搜索引擎抓到，长期收益最大。

### 一个反复出现的问题

音乐播放失败、搜索无结果、打印样式 404、`music-playlist.json` 从没被读过、
giscus 指向旧仓库名 —— 这些都是**出问题时什么都不说**。构建不报错、类型检查
也过，只有真正用起来才发现「怎么没反应」。后续加功能时值得优先问一句：
这个东西失败的时候，用户会看到什么？
